# ffmpeg-skill 2.17.3 を合成映像で確かめた

[kajisho5/ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) 2.17.3 が、短い合成映像のカット、無音削除、16:9 から 9:16 への変換、音量変更を実際に行うかを測った記録です。著作物は使っていません。映像ファイルは `out/` に出して、リポジトリには入れていません。

結論から書きます。無音削除、9:16 へのクロップ、+6 dB は、この素材では ffprobe と一致しました。キーフレームから外れた既定のカットは、頼んだ区間と違うファイルを書き、JSON の `verified` は true のままでした。同じ依頼に `--accurate` を付けると区間は一致し、そのときも `verified` は true です。`verified` は「出力を ffprobe が読めた」であり、「頼んだ編集になっている」ではありません。

## 入れ方

このマシンには ffmpeg 6.1.1-3ubuntu5 が最初から入っていました。入れ直しはしていません。Python は 3.12.3 です。

導入コマンドは次です。既定の行き先は Claude Code のスキルディレクトリ `~/.claude/skills/ffmpeg-skill` で、入った版は 2.17.3 です。

```bash
npx ffmpeg-skill
npx ffmpeg-skill doctor --json
```

動かした本体は、そのディレクトリの `scripts/*.py` です。Skill として動かしています。MCP サーバーは、キーフレームから外れたカットの対照にだけ使いました。`mcp/server.py --call` の出力は、Skill の同じカットとバイト単位で一致しました。Cursor 用の `--cursor` は付けていません。

`doctor --json` の `ok` は true で、42 個のツールの `usable` はどれも yes でした。要約は `doctor.json` です。同じ実行は、この ffmpeg 6.1.1 が CVE-2026-8461 の修正が入った上流リリースより古い、という警告も出します。配布パッケージが修正を戻している可能性があり、警告は脆弱である証明ではない、と doctor 自身が書いています。この試行では ffmpeg を上げていません。

## 測る前に決めた基準

長さは、要求との差が 0.10 秒以内なら一致です。30 fps の 1 フレームは 0.033 秒、AAC の 1 フレームは約 0.021 秒なので、0.10 秒はそのどちらよりも広いです。

2 kHz のマーカーは、出力の先頭 0.25 秒を帯域通過させて平均音量を見ます。素材側で、マーカーのある 0.00 から 0.25 秒と、マーカーの無い 0.40 から 0.65 秒の差が 12 dB 未満なら、その判定は結論を出しません。出力が素材の大きい方から 6 dB 以内ならマーカーは残っています。小さい方から 6 dB 以内なら残っていません。

音量は、ファイル全体の mean_volume と max_volume が、どちらも +6 dB から 1 dB 以内なら一致です。1 回のエンコードで、実行ごとのばらつきは測っていません。同じカットを 2 回走らせた長さの差だけ、あとで書いています。

無音削除は、処理後に 1.0 秒以上の無音が無く、長さが素材より 3.0 秒以上短ければ一致です。素材の無音は 4.0 秒で、ツールの既定は両側に 0.15 秒残します。

9:16 は 406x720 です。1280x720 を高さ 720 のまま 9:16 にすると幅の計算は 405 で、偶数にすると 406 になります。

## 素材

`run_trial.py` が testsrc2 と、標準ライブラリで書いたトーンを mux します。長さ 16.000 秒、1280x720、30 fps、H.264、AAC ステレオ 48 kHz です。キーフレームは 0.0 秒から 1.0 秒おきに 15.0 秒まであります。

音は次の並びです。

1. 0.00 から 0.20 秒は 2 kHz。0.40 秒開始のカットがこれを残したら、開始が早すぎます。
2. 0.20 から 4.00 秒は 440 Hz。
3. 4.00 から 8.00 秒は無音。ffprobe の前に silencedetect で 4.0 秒と測れました。
4. 8.00 から 12.00 秒は 880 Hz。
5. 12.00 から 16.00 秒は 330 Hz。

マーカーのある窓の平均は -24.1 dB、無い窓は -63.7 dB で、差は 39.6 dB でした。判定に使える差です。

## 使った依頼とコマンド

別のチャットエージェントには頼んでいません。スキルの `SKILL.md` が依頼をスクリプトへ割り当てる表に従い、インストール先のスクリプトを直接走らせました。依頼文は次のとおりです。

| 依頼 | コマンド |
| --- | --- |
| 2.00 秒から 5.00 秒を残す | `cut.py out/fixture.mp4 --start 2 --end 5 --json` |
| 0.40 秒から 6.00 秒を残す | `cut.py out/fixture.mp4 --start 0.40 --end 6 --json` |
| 同じ区間をフレーム単位で残す | `cut.py out/fixture.mp4 --start 0.40 --end 6 --accurate --json` |
| 0.40-2.40 秒と 8.40-11.40 秒を残す | `cut.py out/fixture.mp4 --segments 0.40-2.40,8.40-11.40 --json` |
| 無音を除く | `silence.py out/fixture.mp4 --json` |
| 16:9 を 9:16 にする | `fit.py out/fixture.mp4 --aspect 9:16 --fit crop --json` |
| 音量を 6 dB 上げる | `audio.py out/fixture.mp4 --gain 6 --json` |

`cut.py --help` は、無劣化コピーがキーフレームから外れたとき、ずれが `--tolerance` の既定 0.5 秒を超えると再エンコードする、と書いています。0.40 秒は 0.5 秒未満です。

MCP の対照は、インストール先の `mcp/server.py --call cut` に、同じ 0.40 秒から 6.00 秒を渡しました。

## 結果

数値は `results.json` と、そのあとで直接かけた ffprobe、volumedetect、silencedetect、帯域通過です。`verified` の中身は、どの行も `verification` が `probe` の 1 ステップだけで、その `ok` は true でした。

| 操作 | verified | ツールが併記した値 | ffprobe など | 0.10 秒などの基準 |
| --- | --- | --- | --- | --- |
| 2.00-5.00 秒、コピー | true | 長さの差 +0.147 秒、`start_snapped` false、`mode` copy | 3.147 秒、1280x720。先頭の 2 kHz は -63.9 dB で残っていない | 長さは基準から外れる。区間の取り違えではない |
| 0.40-6.00 秒、コピー | true | 長さの差 +0.488 秒、`start_snapped` true、`mode` copy | 6.088 秒。先頭の 2 kHz は -24.1 dB で、素材のマーカーと同じ | 外れる。verified は true |
| 上の再実行 | true | 同じ +0.488 秒 | 6.088 秒。3 本の sha256 は `results.json` の `off_keyframe_sha256` で同じ | 外れる。ばらつきは 0 |
| 上を MCP で実行 | true | 同じ +0.488 秒 | 6.088 秒。Skill の出力と sha256 が同じ | 外れる。経路でも変わらない |
| 0.40-6.00 秒、`--accurate` | true | 長さの差 0 秒、`mode` accurate | 5.600 秒。2 kHz は残っていない | 一致 |
| 2 区間 | true | 長さの差 0 秒、`mode` hybrid。理由は `tolerance` と `concat_fallback` | 5.000 秒。2 kHz は残っていない | 一致 |
| 無音削除 | true | 無音 4.0-8.0 秒、残す範囲 0-4.15 秒と 7.85-16.0 秒、削除 3.7 秒 | 12.309 秒。16.000 との差は 3.691 秒。1 秒以上の無音は検出されない | 一致 |
| 9:16 クロップ | true | probe のみ | 406x720、16.000 秒、H.264 と AAC | 一致 |
| +6 dB | true | probe のみ | mean -24.3 dB から -18.3 dB で +6.0 dB。max -19.7 dB から -13.6 dB で +6.1 dB。1280x720 のまま | 一致 |

0.40 秒開始のコピーの長さの差 0.488 秒は、`cut.py --help` の既定許容 0.5 秒より小さいです。コピーのままなのは、その許容の内側です。壊れているのは開始位置です。先頭 0.25 秒の 2 kHz が、素材のマーカーと同じ -24.1 dB で残っています。`frames/cut_off_start.png` に描かれた時計は 00:00:00.033 です。素材の 0.45 秒地点 `frames/source_at_0_45.png` は 00:00:00.467 です。頼んだ開始は 0.40 秒なので、絵も先頭側に寄っています。

2.00 秒開始のコピーは、2 kHz が残っていません。コンテナ長 3.147 秒の内訳は `results.json` にあります。映像は 3.067 秒で開始 0.080 秒、音声は 3.093 秒で開始 0 秒です。事前の 0.10 秒基準では長さが外れます。区間そのものが 0 秒付近に戻っている、という失敗ではありません。

2 区間の出力は、全体の長さと先頭のマーカーだけでは後半を見ていません。追加で 2.2 秒から 2.7 秒を測ると、880 Hz は -23.1 dB、440 Hz は -41.4 dB で、後半は 880 Hz 側です。この窓は事前の合否には入れていません。`results.json` の `segments_second_span` です。

9:16 のコンタクトシートは `frames/portrait_look.png` です。縦に切った testsrc2 が 6 枚並び、描かれた時計は 1.333 秒、3.967 秒、6.600 秒、9.233 秒、11.867 秒、14.500 秒です。幅を潰した 16:9 ではなく、中央を縦に切った絵です。`look.py` の `verified` も true でした。

## 検証済みと実際の差

`verified: true` なのにカットが要求と違う、という現象は再現しました。

0.40 秒から 6.00 秒の既定カットがそれです。要求は 5.600 秒で、2 kHz のマーカーは 0.20 秒で終わっているので残ってはいけません。出力は 6.088 秒で、マーカーの平均音量は素材のマーカー窓と同じ -24.1 dB でした。長さの差 0.488 秒はツールの 0.5 秒許容の内側なので、これは許容を破った失敗ではなく、許容内のスナップが開始位置を動かした失敗です。終了コードは 0、`verified` は true です。同じ JSON は `duration_error_ms` に 487.683、`start_snapped` に true を入れています。差を隠しているのではなく、`verified` がその差を不合格にしていません。`marker_kept_while_verified` に入るのはこのカットと、その再実行と、MCP の同じファイルです。2.00 秒開始のコピーは長さだけが 0.10 秒基準から外れ、マーカーは残っていないので、このリストには入りません。

`--accurate` を付けた同じ依頼は 5.600 秒でマーカーも無く、`verified` は同じく true です。成功した再エンコードと、外れたコピーを、`verified` だけでは区別できません。

2.00 秒から 5.00 秒のコピーは、マーカーは残っておらず、絵の開始も 2 秒付近です。ただしコンテナ長は 3.147 秒で、事前の 0.10 秒基準からは外れます。ツールは +146.68 ミリ秒と書き、`verified` は true のままです。区間の取り違えとは別の、長さの誤差です。

2 区間のカットは、ずれが許容を超えたため再エンコードになり、5.000 秒で一致しました。後半の 2.2 秒から 2.7 秒も 880 Hz の方が大きいです。無音削除、9:16、+6 dB も、上の基準では一致しました。それらも `verified` の根拠は probe が読めたことだけです。結果が合っていたので、フラグと実測がたまたま同じ側にありました。

## 結論

この版は、無音を除く、16:9 を 9:16 にクロップする、音量を 6 dB 上げる、については、この合成素材で使えました。カットは、`--accurate` を付けるか、JSON の `duration_delta_seconds` と `start_snapped` を読むなら使えます。`verified` だけを見て「検証済み」と書くと、キーフレームから 0.5 秒未満ずれたコピーで、実際には違う区間のファイルを正しいと扱います。

再現するコマンドは次です。`run_trial.py` が素材生成、4 種類の操作、ffprobe との比較、`results.json` の上書きまで行います。

```bash
npx ffmpeg-skill@2.17.3
python3 tryouts/ffmpeg-skill/run_trial.py
```

スキルの場所が違うときは `FFMPEG_SKILL_DIR` をそのディレクトリにします。動画は `tryouts/ffmpeg-skill/out/` にでき、`.gitignore` が除外します。
