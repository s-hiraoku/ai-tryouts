# 指示の量と、モデルが知らない決まり

この記録は、エージェントへの指示を長くすると作業結果が良くなるかを、一つの小さなライブラリで比べたものです。変えたのは指示ファイルだけです。依頼文、採点、モデルの指定は同じです。

## 出典

電通総研テックブログの渡邉真太郎による 2026-08-31 の記事は、効いたのはモデルが自力では埋められない情報の欠落を補う仕組みだけだった、と書いています。あらゆる足場を盛った対照では、品質は上がらず、コストとターンが増えた、とも書いています。記事中の語では、この種の周囲の仕組みをハーネスと呼びます。

記事は [ハーネスエンジニアリングとは何か。盛れば効くのかを確かめる](https://tech.dentsusoken.com/entry/2026/08/31/%E3%83%8F%E3%83%BC%E3%83%8D%E3%82%B9%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%8B%E3%82%A2%E3%83%AA%E3%83%B3%E3%82%B0%E3%81%A8%E3%81%AF%E4%BD%95%E3%81%8B%E2%80%94%E2%80%94%22%E7%9B%9B%E3%82%8C%E3%81%B0%E5%8A%B9) です。ブログ自身のリンクがこの URL で、取得時の状態コードは 200 でした。

依頼で示された投稿は [https://x.com/moneymog/status/2109585066821059051](https://x.com/moneymog/status/2109585066821059051) です。投稿本文は取得できませんでした。クレジットが尽きたためです。記事は、依頼にある主張で検索し、本文を読みました。

## 課題

`task/` は、短い通知を 1 行の文字列にするライブラリです。最初からある `formatBanner` は、`Sale: ¥100` を返します。新しい受領行の関数名、ファイル、戻り値、禁止する API は、コードを読んでも出てきません。既存のバナーを真似すると、円記号の別関数になります。

その決まりは `rules.md` です。短い指示 `instructions/minimal.md` は、この段落だけです。長い指示 `instructions/full.md` は 17,961 文字で、決まりは 391 行目、見出し「速度」の節に一度だけ入っています。対照は `AGENTS.md` を置きません。

決まりの内容は次のとおりです。

`src/notices.js` に `qv_format_notice(title, amount, seed)` を置く。戻り値は、trim した title、` | `、金額の 10 進、` qv | `、seed の UTF-8 SHA-256 の先頭 8 文字（小文字の 16 進）です。金額が 0 以上の整数でなければ `QuillAmountError`、trim 後の title が空なら `QuillTitleError` です。`Date`、`Math.random`、`console`、通貨記号は使いません。`src/index.js` から再エクスポートします。確認コマンドは `npm run quill:check` です。

## 採点

`grade.mjs` は、できあがったモジュールを import して数えます。

正常 4 件は、戻り値の完全一致です。金額の異常 3 件は、エラー名が `QuillAmountError` であることです。空白だけの title は `QuillTitleError` です。既存バナーは `Sale: ¥100` のままです。合計 9 件です。バナー 1 件は、手を付ける前から通ります。未着手の `task/` は 1/9 です。見本の `fixture/` は 9/9 です。

決まり 8 項目は、ファイルがあること、出口から関数が出ること、禁止 API が無いこと、`src/banner.js` が元のままであることです。対象ファイルが無い項目は不成立です。

`npm run quill:check` が見るのはバナーだけです。隠し採点ではありません。スクリプト名は `package.json` にあるので、指示ファイルが無くても見つかります。

## 走らせ方

作業ディレクトリは次で作ります。

```sh
tryouts/harness-size/prepare.sh /tmp/quill-one minimal
```

`minimal` の位置は `full` または `none` にもできます。依頼文は `prompt.txt` です。渡すときに変えるのは、作業ディレクトリのパスだけです。終わったら次で採点します。

```sh
node tryouts/harness-size/grade.mjs /tmp/quill-one
```

Cursor CLI の `agent`（2026.10.01-e373342）はインストールできました。`agent status` は未ログインで、`CURSOR_API_KEY` もありません。CLI では 1 回も実行していません。CLI だった場合の結果は書いていません。

実行したのは、Cursor の generalPurpose エージェント 6 回です。モデル指定は inherit で、親のチャットと同じです。親はこの実行では Grok 4.7 です。トランスクリプトにモデル名の欄はありません。各条件 2 回です。ディレクトリ名と条件の対応は `results.json` にあります。

事前の短い確認では、`AGENTS.md` は初期のシステム文には入っていませんでした。エージェントがディレクトリを見てファイルを開きました。長いファイルを開いた記録では、ツール結果の本文が空です。直後のメモは 391 行目に仕様があると書き、関数名を挙げています。ファイル上の決まりも 391 行目です。

6 回とも、ツール引数は自分のディレクトリの外を指していません。

## 分かったこと

このモデルとこの課題では、知らない決まりがファイルにあると 2 回とも 9/9、無いと 2 回とも 1/9 でした。1/9 の 1 件は、最初からあるバナーです。新しい受領行は 0 件です。

同じ決まりを 17,961 文字の一般論に埋めても、2 回とも 9/9 でした。短い指示より良くはなっていません。この長さでは、埋めた段落は見落としになっていません。長い指示の 2 回は、どちらもメモで 391 行目と関数名を挙げています。

時間は、条件の差とは言えません。長い指示の 2 回は 207.0 秒と 590.0 秒で、その幅は条件のあいだの差より大きいです。プロファイルは取っていません。トークンも無いので、費用が増えたとは測れていません。

`npm run quill:check` は 6 回とも実行されています。コマンド名は `package.json` にあるので、これは指示ファイルの効果ではありません。

## 限界

各条件 2 回です。モデルは 1 種類で、ログにモデル名が残っていません。課題は 1 つです。長いファイルは約 1.8 万文字で、文脈に入ります。途中が落ちるほど長いファイルは見ていません。

CLI が `AGENTS.md` を自動で読む経路は、未ログインのため未実行です。今回見ているのは、エージェントがファイルを開いたあとの結果です。長いファイルのツール結果本文はログに残っていません。見えた根拠は、直後のメモと、採点を通ったコードです。

エージェントは親のシステム文も持っています。6 回とも同じなので、条件の差の説明には使いません。別モデルによる盲検の採点は、追加のエージェント起動が課金設定で拒否されたため行っていません。ここに書いた分数は、`grade.mjs` を再実行した結果です。
